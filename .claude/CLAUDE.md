# プロジェクト指示（常時適用）

このファイルはセッション開始時に必ず読み込まれる。全作業に共通するルールだけを書く。

## 開発の進め方：仕様駆動
- 正（Source of Truth）は `specs/` の画面仕様書（PNG画像）と、`spec-reviews/` で **AI確認OK** になった「修正内容」（仕様書の付属情報）である。
- 画像に書かれている **項目・種別・振る舞い** だけを実装する。書かれていない機能を足さない。
- 仕様が曖昧・矛盾している場合は推測で埋めず、ユーザーに質問する。
- `specs/` は読み取り専用。仕様の変更が必要なら提案だけ行う（変更・削除・追加はフックでブロックされる）。
- 仕様書の不備（未記載・曖昧・矛盾）は `/check-spec` で `spec-reviews/` の確認一覧に記録する。不備を勝手に補って仕様書を直さない。
- 確認一覧の「修正内容」列はユーザー専用。AI は修正状態（AI確認OK／NG）と修正提案だけを更新する。

## 実装の置き場所
- 生成物はすべて `app/` 配下に置く（例：`app/SCR-01_qa.html`）。
- ビルド不要の素の HTML / CSS / JavaScript で作る。
- 画面遷移は仕様書の画面IDに対応するファイルへのリンクで表現する。

## 見た目について
- 仕様書の画像に描かれた配色・装飾は参考扱いとし、見た目はすべて **Material Design 3** で統一する。
- 詳細ルールは `.claude/rules/material-design.md`（`app/` のファイルを扱うときに自動で読み込まれる）。
- 1画面を実装するときは `/implement-screen <画面ID>` スキルの手順に従う。
